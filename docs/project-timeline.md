## 1. 基础知识学习

### 区块链
- 分为公链和联盟链，本质是一种去中心化的分布式账本技术，每个区块通过密码学方式（哈希值）链接到前一个区块，形成一条链。如果有人想篡改中间的某个区块，后面所有区块的链接都会断裂。数据一旦上链，被网络确认后，几乎无法被修改或删除。这不意味着绝对不可改，但改造成本极高，需要控制全网超过半数（51%）的计算能力。

### 去中心化
- 没有单一的中心服务器或管理机构。数据由全网节点共同维护，任何单点故障或恶意篡改都不会影响整体。同时也不依赖于某一主体，解决了信任问题。

### 智能合约
- 运行在区块链上的自动执行程序。它的核心逻辑可以概括为：当预设条件满足时，自动执行约定的操作，无需第三方介入。
- 智能合约不能主动"醒来"，必须由外部交易触发；它也不能自主发起 HTTP 请求，需要依赖预言机来获取链外数据（如天气、股价）。

### P2P
- P2P 是 Peer-to-Peer（点对点） 的缩写，指的是一种去中心化的网络架构，网络中的每个节点（Peer）地位对等，既可以提供服务，也可以消费服务。
- P2P 是区块链的底层基础设施——比特币和以太坊都运行在 P2P 网络上，每个全节点都是一个 Peer，负责转发交易、同步区块。但 P2P 本身是一个更广泛的概念，不限于区块链（eg迅雷下载：不是从服务器下载，用户发给用户，点对点传输数据）。

### LLM
- Large Language Model，即大语言模型，是指那些拥有海量参数、在海量文本数据上训练出来的、能够理解和生成人类语言的深度学习模型。
- GPT-4、Claude Code、Gemini、DeepSeek 等都是大模型

### Token
- Token 是模型处理文本的最小单位。一个 token 可以是一个词、一个词的一部分、或一个标点符号。比如 "blockchain" 可能是 2 个 token，"区块链" 可能是 3 个 token。模型的输入输出按 token 数量计费。
- OpenAI 的 Tokenizer 工具可用于计算 token：https://platform.openai.com/tokenizer

### Context
- 上下文，指模型在一次推理中能够看到的所有信息。通常包括：系统提示（System Prompt），即预先设定的角色描述和行为准则；对话历史；当前输入和额外注入的信息，比如检索到的文档内容等。

### Context Window
- 模型一次推理中能处理的最大 token 数量，它决定了模型能记住多长的对话历史或读懂多长的文档。在 Coding 时，这将直接决定一个模型处理项目的能力。
- 如果上下文很短，模型一次就无法处理太多文件；但如果上下文很长，例如 DeepSeek-V4-Pro 支持 1m 上下文窗口，也即百万 token 上下文输入，你就可以把整个项目发给他让它从整体角度出发处理问题。

### Prompt
- Prompt 就是你跟 AI 对话时输入的文本，它的质量直接决定了 AI 输出的质量。

### Prompt Engineering
- 提示词工程，这是目前一个很重要的技能——研究怎么写 prompt 能让 AI 给出最好的结果。常见技巧包括：
- Chain-of-Thought（思维链）：让模型一步步推理，而不是直接给答案。比如不写 "这道数学题答案是多少"，而是 "请逐步推理，最后给出答案"。
- Role Prompting（角色提示）："你是某领域的专家"——模型会根据角色定位调整回答的口吻和专业度。
- System Prompt（系统提示）：像 Claude 这样的模型有 system prompt 机制——你可以设定一段全局指令，它会影响模型在整个对话中的行为。比如我现在遵循的规则，很大程度上来自我的系统提示。

### AI Agent
- Agent（智能体、代理人），AI Agent 是指以大语言模型为大脑，能够自主感知环境、制定计划、调用工具、执行行动来完成复杂任务的 AI 系统。不再只是简单回答问题，而是能够真正做事情。
- Agent代表了大模型应用的下一个范式跃迁——从聊天工具进化为行动者。

### Agent Skills
- 智能体技能，是指 AI Agent 被赋予的特定领域的能力模块。每个 Skill 封装了完成某一类任务所需的知识、工具、流程和策略，让 Agent 可以像安装插件一样灵活地获取新能力。

### AI Coding Assistant
- AI 编程助手 是一个AI 协作者。它不取代编辑器，而是驻留在编辑器里面或旁边，帮你生成代码、解释代码、修改代码。
- 常见的有 Claude、Cursor、Codex、Github Copilot、ChatGPT 等。

### IDE
- Integrated Development Environment（集成开发环境），把程序员写代码需要的所有工具打包在一个软件里。可以把它理解成一个数字化的程序员工作台——所有工具都在手边，不用来回切换。

### Vibe Coding
- 由 AI 领域知名人物 Andrej Karpathy 在 2025 年初提出，描述一种完全依赖 AI 来写代码的编程方式。你对代码本身不需要完全理解，更多是在描述需求 → 看效果 → 提修改意见这样一个循环里。就像跟着音乐的节奏"摇摆"（vibe），所以叫 vibe coding。

### API
- Application Programming Interface（应用程序编程接口），就是两个软件之间约定好的沟通方式——一个程序怎么去调用另一个程序的功能或数据。

### API Key
- 调用 API 时的身份凭证和访问密钥——相当于你的"钥匙"或"通行证"。

## 4. 后端合约开发 + 部署本地链

### 编写 Solidity 合约
- Solidity 是专门用来写以太坊及兼容公链智能合约的编程语言，语法类似 JavaScript/C++。
- Solidity 合约：用 Solidity 编写、部署在区块链上的自动执行代码，跑在全网节点，去中心化，永久运行。
- 本项目所有链上逻辑都写在合约 [FootballBetting.sol](../contracts/FootballBetting.sol) 中。

### 确立项目构成
- 此时项目构成还较为简单，只有 constract、script、test 和一些其它必要文件。分工也很明确，contract 中存放合约文件，script 中存放部署、演示等一些脚本，test 中存放测试文件。

### 以太坊
- 以太坊是一个开源、去中心化、图灵完备的可编程区块链平台，由 Vitalik Buterin 于 2013 年提出，2015 年 7 月主网上线，核心创新为内置以太坊虚拟机（EVM），支持链上智能合约部署与执行，形成全球分布式状态机，支撑 DeFi、NFT、DAO 等 Web3 生态，原生加密资产为ETH（以太币）
- 作为第二代公链，相比于主打转账 / 价值存储，功能简单但最安全的第一代公链比特币，以太坊主打智能合约、跑应用（DeFi/NFT/ 钱包），是世界上第一条可编程智能合约公链。

### Hardhat 开发框架
- Hardhat 是以太坊生态最主流的 Solidity 智能合约开发框架，专门用来写、编译、测试、部署、调试链上合约。主要功能如下：
- 本地节点 & 本地调试：内置本地模拟区块链，不用上主网 / 测试网，本地跑合约、调用函数，调试零 Gas 成本。
- 单元测试：搭配 JS/TS 写自动化测试，校验合约逻辑、边界条件，提前规避漏洞。
- 脚本部署：一行命令把合约自动部署到测试网、主网。
- 插件生态：可集成验证合约代码、Gas 分析、代码格式化、第三方库等工具。
- 控制台交互：内置交互式终端，直接调用已部署合约的方法。

### Localhost 本地链
- Hardhat 本地节点：启动本地区块链节点后，默认地址就是 http://localhost:8545
- 项目初期部署在本地链上，无前端，所有操作和反馈都在终端上体现。通常的流程是：1. 开启本地链 2. 部署合约 3. 进行演示 4. 反馈结果。期间随时可以 test。

## 5. 结合 PRD 修改后端并做 Code Review

### Gas 减耗
- Gas = 燃料 / 手续费，是以太坊（及同类 EVM 链）里执行智能合约必须消耗的费用。
- 本地链测试虽不消耗 gas，但将来合约上线主网，用户必须支付 gas 才能使用合约，故 gas 的减耗是十分重要的。
- 不论是部署合约、调用合约还是进行任何钱包签名操作，都要消耗 gas。通常情况下，部署合约到链上这一行为消耗的 gas 最多。但由于是一次性操作，所以在减耗方面更多考虑的是用户使用合约时花费的 gas，放在本项目中就是用户下注、领奖时消耗的 gas。PRD 在这方面给出了参考的 gas 消耗上限，来保证本项目不会因为 gas 消耗太高而影响用户的使用体验。

### ETH
- 以太币，是以太坊（Ethereum） 这条公链的原生代币，符号 ETH。
- 在以太坊转账、授权、Swap、交互 DApp，每一笔操作都要消耗 ETH 当手续费。没有 ETH，链上任何操作都无法执行。而且 ETH 本身是主流加密资产，可转账、交易、理财、质押生息。

### USDT
- USDT（泰达币） 是一种稳定币，由 Tether 公司发行，承诺每发行 1 枚 USDT，银行里就存 1 美元储备，用来保证价格稳定。其不像比特币、ETH 一天涨跌很多，USDT 基本围绕 1 美元小幅波动，适合当 “币圈现金”，也适合作为世界杯竞猜的货币。
- 确定 USDT 为本项目所使用的货币，但由于当时还没有前端和连接钱包的功能，遂只停留在概念上，后续将逐步深入。

### Code Review
- 代码审查，也即别人帮你看代码、查问题、提优化建议，是开发里的标准协作流程。结合本项目 Vibe Coding 的开发理念，这一工作自然也交由 AI 来完成。
- 项目进行到此处时，正处于后端编写完成准备开启前端开发的时间节点。秉持解决完所有问题再向前开发的理念，首次对整个项目做了一次 code review。在 AI 的帮助下解决了一些遗留问题，为接下来的前端开发铺平道路。
- 此处强调 code review 这一概念还有另一层考虑，类似于上文提到的 Prompt Engineering，如何准确且高效地向 AI 表达你的需求，让 AI 精确地完成你想要让他为你完成的工作，措辞的准确性是尤为重要的。而 code review 作为一个地道的行业内表达，本身就是该案例的良好体现。这就和开启本项目的初衷之一相吻合，即学会如何更好的使用 AI，从与 AI 的交流开始。

## 7. 连接钱包 + 修复前端 Bug

### 加密货币钱包（Web3 钱包）
- 这类属于非托管 Web3 浏览器钱包，专门用来管理链上资产、连接去中心化应用 (DApp)，是进入区块链 / DeFi/NFT 世界的入口。
- 非托管 = 资产完全归你：私钥 / 助记词只存在你本地设备，平台拿不到，不会卷走你的币；但丢了助记词 = 资产永久丢失。
- 浏览器扩展形态：装在 Chrome / 火狐 里，不是传统 APP，主要用来上网页 DApp。
- 助记词：12/24 个英文单词，= 钱包所有权，只有用户自己知道，一但忘记无法找回。
- 私钥：记词换算而来，等价于助记词。
- 公钥 / 钱包地址：对外收款地址，可以公开分享。
- 授权 / 无限授权：允许 DApp 动用你钱包里的代币。
- 钱包签名：用你的私钥做 “身份盖章”。区块链里没有账号密码登录，钱包依靠私钥生成签名，用来证明：这笔操作 / 请求，确实是钱包本人发起的，不是别人伪造的。
- Nonce = Number used once（只使用一次的数字）：地址发出交易的 “序号 / 流水号”，用来防重复、保顺序、防盗刷。

### Rabby
- Rabby 是 DeBank 团队推出的开源、非托管、EVM 多链浏览器钱包，主打交易前模拟 + 风险可视化 + 自动切链，被称为 “更安全的 MetaMask 替代”。界面简洁、中文友好，新手易上手。但仅支持 EVM 链，不支持 Solana、Bitcoin 等非 EVM。
- 由于一开始对钱包的不了解，没有完成对 MetaMask 钱包的注册，故先使用的是 Rabby。结合本地链的环境，可以很好的完成测试。

### 连接钱包测试
- Hardhat 启动本地节点时会同时打印每个账户的地址和私钥，但往钱包里导入测试账户时，必须用私钥。光有地址只能查看余额，无法签名发起交易（投注、领奖等操作都需要私钥签名）。操作流程：复制 Hardhat 节点启动时打印的私钥 → 在 MetaMask 里 "导入账户" → 粘贴私钥 → 完成导入。
- 当时有一个反复出现的问题：由于测试时频繁修改合约，导致本地链频繁重新部署，而每次重启 Hardhat 本地节点，链上数据就完全重置了 — 所有账户的 nonce 都回到 0。但钱包（MetaMask / Rabby）并不知道链被重置了，它还记得上次发到第几笔交易（比如 nonce=5），于是下一笔就用 nonce=6 去签名，Hardhat 收到后报错。最后的解决办法是：每次重启 Hardhat 节点后，在钱包里 Reset Account（MetaMask：设置 → 高级 → 重置账户），把钱包记录的 nonce 也清回 0，两边就对齐了。

### 初始货币
- 由于 Hardhat 默认货币是 ETH，所以最开始在创建测试账户时就会自动给予一定量的 ETH 作为燃料费和竞猜币，但随着 USDT 作为竞猜币的确定，部署时改为向测试账户同时发放 ETH 和 USDT，分别作为燃料费和竞猜币。当时还考虑过使用多种货币兼容的竞猜模式，但结合合约逻辑的复杂程度以及 PRD 发起人提出的后续上限树图链的需求，最终放弃使用多货币支付，改为燃料费与竞猜币币种分离，USDT 作为单一竞猜货币类型的形式。
- 由于现阶段的 USDT 没有实际背景，故本质上只是我自定义命名的一种代币，钱包识别不到，所以需要手动添加代币。但这又引出了另一个当时令我百思不得其解问题：代币的小数位数。

### 代币小数位数
- 区块链代币本质是链上整数记账，不存在小数。开发者提前约定：1 枚主币 = 10^N 个最小记账单位，这里的 N 就是小数位数。
- 以 ETH / CFX（小数位 18）为例：底层记最小单位 Wei / Drip，规定：\(1\ \text{币} = 10^{18}\ \text{最小单位}\)，链上记账：1000000000000000000 Wei → 钱包显示：1 ETH
- 核心：链上全是整数运算，小数只是前端展示效果。

## 8. 连接 MetaMask 钱包 + 开启多用户测试

### Gas 减耗
