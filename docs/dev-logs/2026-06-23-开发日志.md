## 二、合约层改动（FootballBetting.sol）

### 2.1 Gas 优化第四轮 — 自定义错误

**问题**：合约有 35+ 个 `require` 语句，每个附带 20-50 字符的错误信息字符串。这些字符串存储在字节码中，每次 revert 时还需完整编码。

**修改**：定义 36 个自定义错误，替换全部 `require` 为 `if + revert CustomError()`。

```solidity
// 旧写法
require(startTime > block.timestamp, "FootballBetting: start time must be in the future");

// 新写法
error StartTimeNotFuture();
if (startTime <= block.timestamp) revert StartTimeNotFuture();
```

**效果**：

| 指标 | 优化前 | 优化后 | 节省 |
|---|---|---|---|
| 部署字节码 | 含 35+ 条错误字符串 | 仅 4 字节 selector | ~5-10% |
| 每次 revert | 完整字符串编码 | 4 字节 selector | ~200-300 gas |

### 2.2 unchecked 池子运算

**问题**：`_addToPool` 和 `_removeFromPool` 中的 uint128 加减每次触发 Solidity 0.8.x 的溢出检查，但 USDT 总供应量远低于 2^128，溢出不可能发生。

**修改**：用 `unchecked` 包裹两个函数的全部运算。

**效果**：每次投注节省 2-4 次溢出检查（~100-400 gas）。

### 2.3 修复 placeBet 双写 SSTORE

**问题**：`placeBet` 中用户切换投注选项时：

```solidity
b.betOn = betOn;
b.amount = betAmount;   // SSTORE slot 0（amount+reward 共槽）
b.reward = 0;           // 又 SSTORE slot 0，浪费 ~5000 gas
```

**修改**：先写 `b.reward = 0` 再写 `b.amount = betAmount`，让 Solidity 将两次同槽写入合并为一次。

**效果**：切换选项时节省 ~5000 gas。

### 2.4 deleteMatch 简化 — 移除编号补位

**问题**：删除比赛后，后续所有比赛编号依次左移补位（#3→#2, #4→#3...），逻辑复杂且易出错。

**修改**：直接 `delete matches[matchId]` 在原位删除，不再移动后续比赛。

**影响**：比赛编号可能出现间隔（如 #1、#3、#5），但对用户无感知影响。前端已通过 `startTime > 0` 过滤被删除的比赛。

### 2.5 withdrawFee 新增 noReentrancy

**修改**：为 `withdrawFee` 添加 `noReentrancy` 修饰器，与其他写函数保持一致。

## 四、前端核心修复

### 4.1 useIsAdmin — 同时检查 owner 和 admins

**问题**：`useIsAdmin` 只对比 `address === owner`，被 `addAdmin` 添加的地址在前端看不到管理页面入口。

**修改**：使用 `useReadContracts` 批量查询 `owner()` 和 `admins(address)`，`isAdmin = isOwner || isInAdmins`。

```typescript
// 旧
const { data: owner } = useReadContract({ functionName: "owner" });
isAdmin: address === owner;

// 新
const { data } = useReadContracts({
  contracts: [
    { functionName: "owner" },
    { functionName: "admins", args: [address] },
  ],
});
isAdmin: isOwner || isInAdmins;
```

### 4.2 彻底移除 Conflux 主网

**原因**：主网尚未启用，残留代码和配置增加维护负担 + SSR hydration 风险。

**修改**：

| 文件 | 改动 |
|---|---|
| `frontend/src/lib/wagmi.ts` | 删除 `confluxMainnet` 链定义、`ENABLE_LOCAL` 条件判断、主网注释 |
| `frontend/src/lib/config.ts` | 删除 `confluxMainnetData` import 和 `DEPLOYMENTS[1030]` 条目 |
| `hardhat.config.ts` | 删除 `confluxMainnet` 网络配置和 etherscan customChain |

**附带修复**：`ENABLE_LOCAL` 使用 `window.location` 在 SSR 时不可用，移除后消除 hydration mismatch 风险。

### 4.3 类型安全 — 消除全部 as any

**问题**：几乎所有组件都在用 `as any` / `as any[]` 处理合约返回值。ABI 变更时无编译时错误。

**修改**：

创建 `frontend/src/lib/types.ts` 统一定义合约返回类型：

```typescript
export interface MatchStruct {
  matchName: string; homeTeam: string; awayTeam: string;
  poolHome: bigint; poolDraw: bigint; poolAway: bigint;
  totalPool: bigint; minBet: bigint; maxBet: bigint;
  startTime: bigint; deadline: bigint;
  result: number; status: number;
  homeScore: number; awayScore: number;
  settled: boolean; allowDraw: boolean;
}

export type UserBetTuple = [bigint, number, bigint, bigint, boolean];

export interface UserBetData {
  amount: bigint; betOn: number; timestamp: bigint;
  reward: bigint; claimed: boolean; hasBet: boolean;
}

export type UserAllBetsTuple = [bigint[], bigint[], number[], bigint[], boolean[]];
```

**影响的 13 个文件**：所有页面、hooks、MatchCard 组件均替换为 `MatchStruct` / `UserAllBetsTuple` / `UserBetData` 等明确类型。TypeScript 编译零错误。

### 4.4 parseContractError 适配自定义错误

**问题**：合约改用自定义错误后，revert 信息不再包含原 `require` 字符串，前端无法匹配。

**修改**：`errors.ts` 重写，同时匹配新错误名（如 `NotOwner`）和旧 require 字符串（如 `caller is not the owner`），确保新旧合约都兼容。

### 4.5 ABI 文件同步

合约重新编译后，`FootballBetting.json` ABI 包含 36 个自定义错误条目，同步复制到 `frontend/src/lib/abi/`，viem 才能正确解码 revert 错误。
