一、项目概述

1.1 项目背景

2026年世界杯正在进行中，我们希望借此热点，结合公司区块链技术优势，开发一个去中心化的世界杯竞猜（预测）系统。该项目作为实习生的实践项目，采用纯 Vibe Coding（AI 辅助编程）方式完成开发。

1.2 项目定位

一个部署在区块链上的 去中心化世界杯赛事竞猜 DApp，用户可以使用加密货币对世界杯比赛结果进行预测，预测正确的用户按比例瓜分奖池。

1.3 核心价值主张

传统竞猜平台的痛点我们的区块链方案
资金不透明，存在跑路风险智能合约托管资金，链上可查
开奖规则可被篡改规则写入合约代码，不可篡改
中心化平台抽成过高规则透明，手续费极低且公开
用户隐私泄露钱包地址参与，无需实名

1.4 技术选型建议

层级建议技术说明
智能合约Solidity以太坊生态最主流的合约语言
部署网络EVM 兼容测试网（Sepolia / 公司自有测试链）降低开发成本，方便演示
前端React / Next.js主流 Web 框架，AI 生成代码质量高
钱包交互ethers.js / wagmi + RainbowKit连接 MetaMask 等钱包
赛事数据源管理员手动录入（MVP 阶段）后期可接入预言机（Chainlink）

2.2 角色详细说明

管理员（Admin）

  • 身份：智能合约的部署者/Owner
  • 权限：创建赛事、设置赔率规则、录入比赛结果、触发开奖、紧急暂停合约
  • 数量：1个（合约 owner 地址）

普通用户（Player）

  • 身份：已连接钱包的区块链用户
  • 权限：浏览赛事、参与竞猜下注、查看个人竞猜记录、领取奖励
  • 数量：不限

访客（Visitor）

  • 身份：未连接钱包的浏览者
  • 权限：浏览赛事列表、查看比赛详情与奖池信息
  • 数量：不限

B-05 投注校验规则

前端校验（提交前）：

校验项规则不通过时提示

网络正确必须在目标网络"请切换到正确网络"
赛事状态必须为 OPEN"该赛事已停止投注"
时间校验当前时间 < 截止时间"投注时间已截止"
选项选择必须选择一个选项"请选择竞猜选项"
金额 > 0投注金额必须大于 0"请输入投注金额"
金额 ≥ 最低不低于最低投注额"投注金额不能低于 X ETH"
金额 ≤ 最高不超过最高投注额（如有设置）"投注金额不能超过 X ETH"
余额充足钱包余额 ≥ 投注金额 + 预估Gas"余额不足"

合约校验（链上二次校验）：

  • 赛事存在性验证
  • 赛事状态验证（必须为 OPEN）
  • 时间戳验证（block.timestamp < deadline）
  • 金额验证（msg.value >= minBet）
  • 选项合法性验证（0=主胜, 1=平局, 2=客胜）

  • 主队进球 > 客队进球 → 结果 = 主队胜（选项 0）
  • 主队进球 = 客队进球 → 结果 = 平局（选项 1）
  • 主队进球 < 客队进球 → 结果 = 客队胜（选项 2）

S-03 奖金计算规则 — 详细说明

采用「奖池分配制（Parimutuel）」：

所有投注汇入总奖池，扣除平台手续费后，按胜出者的投注金额比例分配。

计算公式：

TEXT
总奖池 = 所有投注金额之和

平台手续费 = 总奖池 × 手续费比例（建议 2%~5%，MVP 阶段建议 2%）

可分配奖池 = 总奖池 - 平台手续费

某胜出用户的奖金 = 可分配奖池 × (该用户投注金额 / 所有胜出用户投注金额之和)

举例：

TEXT
比赛：巴西 VS 德国
总投注：10 ETH
  - 巴西胜：4 ETH（3人投注：A投2, B投1.5, C投0.5）
  - 平局：  2 ETH
  - 德国胜：4 ETH

实际结果：巴西胜

平台手续费（2%）= 10 × 0.02 = 0.2 ETH
可分配奖池 = 10 - 0.2 = 9.8 ETH

用户A的奖金 = 9.8 × (2 / 4) = 4.9 ETH（净赚 2.9 ETH）
用户B的奖金 = 9.8 × (1.5 / 4) = 3.675 ETH（净赚 2.175 ETH）
用户C的奖金 = 9.8 × (0.5 / 4) = 1.225 ETH（净赚 0.725 ETH）

特殊情况处理：

场景处理方式
没有人猜中正确结果所有投注原路退回（扣除 Gas 费），或全部归入平台（建议退回，体验更好）
某个选项无人投注正常结算，不影响其他选项
只有一个人参与投注若猜中，获得自己的投注减去手续费；若未猜中，退回投注

R-02 领取奖励 — 详细说明

采用「Pull」模式（用户主动领取）而非「Push」模式（系统自动发放）：

原因：Push 模式需要管理员批量发送交易，Gas 费高且可能失败；Pull 模式更安全，是智能合约最佳实践。

领取流程：

TEXT
用户在「我的投注」页面看到某赛事状态为「已开奖」
    → 如果该赛事用户猜中了
        → 显示可领取金额：X.XX ETH
        → 显示「领取奖励」按钮
        → 用户点击「领取奖励」
        → 唤起钱包确认交易（此交易 Gas 费由用户承担）
        → 交易上链成功
        → 奖金到账用户钱包
        → 按钮变为「已领取 ✅」
    → 如果用户未猜中
        → 显示「未中奖」标识
        → 无领取按钮

4.2 核心数据结构

SOLIDITY
// 赛事状态枚举
enum MatchStatus {
    OPEN,       // 0: 投注中
    CLOSED,     // 1: 已封盘
    SETTLED,    // 2: 已开奖
    FINISHED    // 3: 已结束
}

// 投注选项枚举
enum BetOption {
    HOME_WIN,   // 0: 主队胜
    DRAW,       // 1: 平局
    AWAY_WIN    // 2: 客队胜
}

// 赛事结构体
struct Match {
    string homeTeam;          // 主队名称
    string awayTeam;          // 客队名称
    uint256 matchTime;        // 比赛时间
    uint256 deadline;         // 投注截止时间
    uint256 minBet;           // 最低投注额
    uint256 maxBet;           // 最高投注额（0=不限）
    MatchStatus status;       // 赛事状态
    uint8 homeScore;          // 主队进球
    uint8 awayScore;          // 客队进球
    BetOption result;         // 比赛结果
    uint256[3] totalBets;     // 三个选项的总投注额 [主胜, 平局, 客胜]
    uint256 totalPool;        // 总奖池
    uint256 participantCount; // 参与人数
}

// 投注记录结构体
struct Bet {
    uint256 matchId;        // 赛事ID
    BetOption option;       // 投注选项
    uint256 amount;         // 投注金额
    uint256 timestamp;      // 投注时间
    bool claimed;           // 是否已领取奖励
    uint256 reward;         // 可领取奖金（开奖后计算）
}

六、非功能性需求

6.1 安全性要求

安全项要求说明
重入攻击防护必须使用 ReentrancyGuard 或 Checks-Effects-Interactions 模式
整数溢出防护必须Solidity 0.8+ 内置溢出检查
权限控制必须管理员函数必须有 onlyOwner 修饰器
紧急暂停建议实现 Pausable 机制，紧急情况下可暂停合约
前端输入校验必须所有用户输入进行合法性校验

6.2 用户体验要求

体验项要求
加载状态所有链上查询和交易操作都需要 loading 状态提示
错误处理交易失败时需要友好的错误提示（翻译合约 revert 原因）
响应式设计支持桌面端和移动端浏览器（优先桌面端）
交易确认重要操作（投注、领取）需要二次确认
实时更新投注后奖池数据应及时刷新（可手动刷新或监听事件）

6.3 性能要求

性能项要求
页面加载首屏加载时间 < 3秒
合约 Gas单次投注 Gas 消耗应合理（< 200,000 gas）
数据读取链上数据读取应使用 view 函数，不消耗 Gas

九、给实习生的几点建议

9.1 Vibe Coding 技巧

  1. 需求拆解：把每个功能点单独作为一个 prompt 让 AI 生成代码，不要一次性让 AI 写完整个项目
  2. 理解代码：AI 生成的每一段代码，务必理解其逻辑，不懂就追问 AI
  3. 渐进式开发：先跑通最小流程（创建赛事→投注→开奖→领奖），再逐步丰富功能
  4. 善用 AI Debug：遇到报错直接把错误信息丢给 AI，让它帮你排查

9.2 关键知识点（可让 AI 解释）

  • 什么是智能合约？什么是 Solidity？
  • 什么是 ABI？前端怎么调用合约？
